# Stack-Based Mathematical Expression Evaluator

A Python program that reads mathematical expressions from a text file (`input.txt`), evaluates each one using a **stack-based approach**, and writes the results to another text file (`output.txt`) in the same layout as the input.

## 4. Input file structure (`input.txt`)

* Each mathematical expression is on **its own line**.
* Expressions are separated by a line containing **only dashes** (three or more), for example `-----`.
* Blank lines are allowed and are kept as blank lines in the output.

Example:

```
3 + 5 * 2
-----
(8 / 4) + 7 * 2
-----
10 - (2 + 3) * 4
```

Supported in an expression: whole numbers, decimal numbers (`3.5`, `.25`), the operators `+ - * /`, parentheses `( )` (including nested), and a unary minus or plus (`-5 + 12`, `7 - -3`). Spaces are optional (`3+5*2` works).

## 5. Output file structure (`output.txt`)

* The output has the **same format as the input**: every expression line is replaced by its result, and the separator lines are copied exactly.
* One result per line.
* Whole-number results are written without a decimal point (`13`, not `13.0`). Other results are rounded to at most 6 decimal places with trailing zeros removed (`10 / 3` → `3.333333`).
* If an expression is invalid, its line contains `Error: <reason>` and the program continues with the next expression.

Output for the example above:

```
13
-----
16
-----
-10
```

## 6. How the program works (summary)

The program uses a custom `Stack` class (`push`, `pop`, `peek`, `is_empty`, `size`) and the classic **two-stack algorithm**:

* an **operand stack** holds numbers,
* an **operator stack** holds operators and opening parentheses.

When an operator arrives, every operator on the stack with *higher or equal precedence* is applied first (`*` and `/` bind tighter than `+` and `-`, and equal-precedence operators are applied left to right). A closing parenthesis applies operators back to the matching opening parenthesis. At the end of the line, the remaining operators are applied and the single value left on the operand stack is the result.

Main functions:

| Function | Role |
|----------|------|
| `Stack` | Stack data structure (push, pop, peek, etc.) |
| `tokenize()` | Splits an expression into numbers, operators and parentheses |
| `apply_operator()` | Pops operand(s), applies one operator, pushes the result |
| `evaluate_expression()` | Evaluates one expression using the two stacks |
| `read_input_file()` | Reads the lines of the input file |
| `evaluate_lines()` | Evaluates every expression and stores the results |
| `write_output_file()` | Writes the results to the output file |

## 7. Error handling

| Problem | Output |
|---------|--------|
| Division by zero, e.g. `8 / (4 - 4)` | `Error: Division by zero` |
| Missing `)`, e.g. `(3 + 4` | `Error: Mismatched parentheses: missing ')'` |
| Extra `)`, e.g. `3 + 4)` | `Error: Mismatched parentheses: unexpected ')'` |
| Missing operand, e.g. `3 + * 4` or `3 +` | `Error: Missing operand before '*'` / `Error: Expression ends with an operator (missing operand)` |
| Missing operator, e.g. `3 4` | `Error: Missing operator before number` |
| Unsupported character, e.g. `5 $ 3` | `Error: Invalid character '$'` |
| If the input file does not exist | A message is printed and the program stops safely |

## 8. Assumptions and limitations

* Only the four operators `+ - * /` are supported (no powers, modulus, functions or variables).
* Implicit multiplication such as `2(3)` is **not** accepted; write `2 * (3)`.
* Calculations use Python floating-point numbers, so results are rounded to 6 decimal places in the output.
* A separator line must contain only dashes (three or more). A line such as `---5` is treated as an expression, not a separator.
* The input file is read as UTF-8 text.
* **Note on the sample in the assignment brief:** the brief shows `17` as the result of `(8 / 4) + 7 * 2`. Working it out by hand gives `8 / 4 = 2`, `7 * 2 = 14`, and `2 + 14 = 16`, so the program correctly outputs `16`. The other two examples (`13` and `-10`) match the brief exactly.
